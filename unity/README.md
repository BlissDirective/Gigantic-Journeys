# `unity/`

Owner: gj-gameplay (project), gj-capture (Assets/Capture), gj-avatar (Assets/Avatar), gj-design (Assets/UI). Ticket: **M0-UNITY-01** (Unity 6 URP scaffold).

The Gigantic Journeys Unity 6 project. This README is the **authoritative project spec**: CI, the QA VM, and the Mac runner must match the pinned editor version, and the first Editor open follows the finalization runbook below. A Unity project's final form (ProjectSettings, `.meta` GUIDs, URP pipeline assets, `Packages/packages-lock.json`) is generated by the Editor, so those land in the **first-Editor-open** step (a computer-use step, routed to the Operator / QA VM per `AGENT_GOVERNANCE.md §2`), not by hand.

## Pinned editor version (match everywhere)
- **Unity `6000.0.28f1`** (Unity 6.0 LTS), pinned in `ProjectSettings/ProjectVersion.txt`.
- If the exact patch is unavailable, install the nearest **6000.0 LTS** patch and update `ProjectVersion.txt` **and** this line together, then re-pin `Packages/packages-lock.json`. CI (game-ci), the QA VM, and the Mac runner all read this version.

## Identity (apply in Project Settings → Player on first open)
- Product Name: **Gigantic Journeys**
- Company Name: **SparkForge Labs**
- Bundle Identifier (iOS **and** Android): **`com.sparkforgelabs.giganticjourneys`**

## Render + build targets
- **URP** (Universal Render Pipeline 17.x, pinned in `Packages/manifest.json`). Create the pipeline + renderer assets under `Assets/Settings/` on first open and assign them in **Graphics** and per **Quality** tier.
- **iOS is the v1 ship target** (AUTH #003): Metal graphics API, **IL2CPP** scripting backend, symbols stripped in release (SECURITY_CHECKLIST §9.7).
- **Android stays buildable but is not shipped in v1**: keep the build target installed so it compiles on demand (`.github/workflows/android-build.yml`), but iOS is the only release target.
- **Quality tiers**: automatic best-possible on newer iPhones, lower tiers keep older iPhones playable (SPEC §6); one URP pipeline asset per tier.

## Pinned packages (`Packages/manifest.json`)
Feature packages, exact-pinned: URP `com.unity.render-pipelines.universal`, Input System `com.unity.inputsystem`, Animation Rigging `com.unity.animation.rigging`, Test Framework `com.unity.test-framework`, uGUI + UI Toolkit runtime `com.unity.ugui`, plus the standard Unity 6 built-in modules. On first open the Package Manager resolves these and writes `Packages/packages-lock.json` — **commit it** so resolution is deterministic across CI/VM/runner. If PM reports a version mismatch for this editor, accept its compatible version and commit the updated `manifest.json` + `packages-lock.json`.

## First-Editor-open finalization runbook (computer-use step → Operator / QA VM)
Needs Unity `6000.0.28f1` installed and, for CI test/build runs, the Unity license secret (`UNITY_LICENSE`, ticket M0-REPO-03). Do it once; commit the Editor-generated files.
1. Open `unity/` in Unity `6000.0.28f1` (create from the **Universal 3D** template if starting fresh, then align to this spec).
2. Let the **Package Manager resolve**; commit `Packages/packages-lock.json`.
3. **Player settings**: set the identity above; iOS → Metal + IL2CPP; keep Android buildable.
4. **URP**: create pipeline + renderer assets under `Assets/Settings/`, assign in Graphics + each Quality tier.
5. **Test assemblies**: create the EditMode and PlayMode asmdefs above with one passing smoke test each (`Assert.Pass()`-level).
6. **Format**: run `csharpier check unity/Assets` (install `csharpier 1.3.0`); fix any formatting.
7. **Verify**: project opens with **zero console errors**; `git status` is clean after opening (Library/Temp are git-ignored).
8. **Tests**: `Unity -batchmode -nographics -runTests -testPlatform EditMode` and `PlayMode` pass; save logs under `qa/reports/M0-UNITY-01/`.
9. Commit `ProjectSettings/**`, `Packages/packages-lock.json`, `Assets/**` (with `.meta` files). CI's `unity tests gate` + `ios-build` activate once `UNITY_LICENSE` is set.
